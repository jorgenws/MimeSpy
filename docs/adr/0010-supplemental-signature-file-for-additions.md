# Additions to the signature table live in a separate, supplemental file

Real ODF fixtures pulled into `MimeSpy.IntegrationTests` from Apache Tika's test corpus surfaced two gaps. First, `ods`/`ots`/`otp` have no entry anywhere in `file_signatures.csv`; combined with `ZipContainerSniffer`'s ODF content-sniffing (docs/adr/0002) always answering `"odt"` for any `application/vnd.oasis.opendocument*` mimetype content regardless of what it actually said, a real `.ods` file's stored `mimetype` entry narrowed it straight into the `odt`/`odp`/`ott` tied group - not just unreachable, actively wrong. We fixed the sniffer to read the mimetype entry's exact value and map it to the matching extension.

That still left `odt`/`odp`/`ott` tied to each other: `file_signatures.csv`'s own "OpenDocument template" row bundles all three into one row's `Extensions` list, as if they were interchangeable aliases the way `jpg`/`jpeg` genuinely are, rather than three unrelated formats (text/spreadsheet/presentation) that just happen to share a header and were never split upstream. Since we now had a way to tell them apart from real content anyway, leaving them tied at the table level would have thrown that away. So the fix isn't just additive: a supplemental-file row sharing a base row's exact header bytes and offset *claims* its own extensions away from that base row (`SignatureIndex.Merge`) instead of only tying alongside it. The supplemental file now declares six independent, single-extension rows (`odt`, `ott`, `ods`, `ots`, `odp`, `otp`) - mirroring how `zip`/`jar`/`apk` already are their own separate rows despite sharing the identical header - and the merge subtracts all six from the upstream bundled row, which is left with nothing and dropped. Each subtype now narrows to exactly itself.

Second, and the reason this needed a new file rather than edits to rows in place: `file_signatures.csv` is a straight copy of Gary Kessler's table (see the root README) that needs to stay swappable for a newer copy of the same file without hand-merging our own changes back into it. So both the new rows and the claim-away-from-upstream corrections live in `file_signatures_supplemental.csv`, same row format, no header row, merged into the same in-memory index at load time rather than edited into the original. Future corrections of this shape belong there too.
